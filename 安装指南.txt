llama.cpp Router 后台常驻 - 中文使用说明
========================================

一、本工具是什么
---------------
把 llama.cpp 的 router 模式（一个 llama-server 实例托管多个模型，
请求里指定 model 名就自动切换）封装成 Windows 后台服务：
  * 开机自启
  * 崩溃自动重启
  * 关闭终端窗口不影响运行
  * 空闲 N 秒自动卸载模型释放显存

二、文件清单
-----------
config.json            唯一配置数据源（UI 与 ini 都从这里派生）
router-preset.ini      由 config.json 自动生成（请勿手工改）
manager-ui.bat         【推荐入口】双击打开可视化界面
install-router.bat     一键安装为后台服务（需要管理员）
uninstall-router.bat   卸载后台服务（需要管理员）
router-run.bat         前台运行（测试用，关闭窗口即停）
status-router.bat      查看服务状态 + 最近日志
test-router.bat        测试所有启用模型的切换
*.py                   业务逻辑（不用关心）
安装指南.txt           本文件

三、第一次安装（拷贝到新电脑后的步骤）
-------------------------------------
0. 确认本机已安装 Python 3.8 或更高版本
     - cmd 中执行:  py --version
     - 没有的话到 https://www.python.org 下载安装
     - 安装时勾选 "Add python.exe to PATH"
     - 备注：tkinter 是 Python 自带的，无需额外安装

1. 把本文件夹放在任意位置（建议放到纯英文路径下，
   避免和系统路径有冲突）

2. 双击 manager-ui.bat 打开可视化界面
     - 如果弹「需要管理员」就右键 → 以管理员身份运行
     - UI 会自动检查环境并提示问题

3. 在 UI 中：
     a) 「全局」页：检查 llama_dir 是否指向你的 llama.cpp 目录
        （含 llama-server.exe 的那个目录）
     b) 「全局」页：按需调整端口、空闲卸载时间等
     c) 「模型」页：增删改模型条目；可以填多模态 mmproj 路径；
        推测解码用「启用推测解码」勾选开启，草稿文件可选
     d) 切到「服务」页 → 点「安装服务」
     e) 等待「服务已安装并启动 (网关)」

4. 浏览器访问  http://127.0.0.1:8080/v1/models
   看到模型列表即为成功。列表里**主池和 KVMem 两组模型都在**
   （每条的 tags 是 pool 或 kvmem）—— 服务跑的是网关 gateway.py，
   它按请求里的 model 名把流量转给对应后端。

四、日常使用
-----------
* 改配置后 → UI「服务」页 → 点「重启」即生效
* 临时停服务 → UI「服务」页 → 点「停止」
* 卸服务   → 双击 uninstall-router.bat（管理员）
* 看日志   → UI「服务」页底部日志框，或 status-router.bat
* API 调用：base_url  = http://127.0.0.1:8080/v1
           model     = 配置里每个模型的 alias 字段（主池和 KVMem 两组
                       共用这个地址，写谁的名字网关就转给谁）
* 命令行测试：双击 test-router.bat
* 远程看日志：UI「监控」窗口地址栏填对方地址即可。
  前提是对方那台也跑本软件，并且在「全局」页勾上「日志转发」。
  连不上时窗口会直接告诉你原因；如果是超时，多半是 Windows
  防火墙在静默丢包 —— 在**远程那台**点「🛡 放行端口」一键加规则
  （会弹 UAC；拒绝提权时按提示手动跑那条 netsh 命令）。
* 用过的地址会记在地址栏下拉里（⚙ 历史设置可改条数、可清空），
  点一下就自动连上，存在 user_preferences.json，不会进发布包。

五、模型设置
-----------
在「模型」页，每个模型有：
  * ID          段名（英文+短横线），API 中通常用不到
  * alias       API 请求里填的 model 名，简洁好记
  * model       主模型 .gguf 绝对路径
  * mmproj      多模态投影文件（视觉模型需要）
  * 推测解码    勾选「启用推测解码」独立开关
  * 草稿模型    MTP/DFlash 草稿 .gguf 路径（可选：模型自带
                草稿权重时留空）
   * 草稿类型    留空按文件名猜 (mtp-/dflash-/dspark-)，
                 也可手动选 draft-mtp / draft-dflash 等；
                 无草稿文件时必须手动选类型
   * 启用        取消勾选 = 不加入 preset.ini（暂不用）
   * 参数子表    每个参数有「启用开关 + 值」两个控件：
                 启用 + 填值 → 才会写入 ini
                 取消启用 → 该参数不写入，沿用 llama.cpp 默认
    * 草稿高级参数  草稿面板底部「高级 (可选)」六项，各自带勾选框：
                  spec-draft-device / threads / threads-batch /
                  type-k / type-v / backend-sampling
                  勾选 + 填值 → 才写入 ini；不勾就不写，
                  草稿总开关关闭时一律不写入（设置保留）
    * 推测类型    草稿面板里的「推测类型」= spec-type，
                  参数子表不再重复出现（子表那份会被面板值覆盖）
    * 快捷参数勾选  草稿面板里直接显示的 7 项，每项自带勾选框：
                  草稿模型 .gguf / 推测类型 / n-max / n-min /
                  p-split / p-min / 草稿 GPU 层数
                  勾选 → 才写入 preset.ini；取消勾选 → 这行彻底不写，
                  且该项控件自动置灰。设置保存在模型配置里，
                  重新选中该模型会原样回读。老配置默认全部勾选，
                  与升级前的输出完全一致。
    * 视觉模型 / KV 内存加载  贴在「推测解码」下方的折叠区块
                  （开关栏常驻、默认折叠、点开关展开）。
                  面板是固定高度 + 纵向滚动条 + 鼠标滚轮，
                  窗口矮也不怕：滚轮一滚就能看完全部 12 项。
                  12 项分三组：
                  视觉模型(mmproj)：mmproj-auto / mmproj-offload /
                      mmproj-device / 图像 min|max tokens / 多模态批 tokens
                  KV 缓存：kv-offload / kv-unified / cache-ram /
                      cache-type-k / cache-type-v
                  模型加载：load-mode
                      (auto / none / mmap / mlock / mmap+mlock / dio)
                  每项自带勾选框：勾了才写入 preset.ini，
                  不勾就沿用 llama.cpp 默认值。这 12 项不会在右侧
                  「常用 / 扩展参数」子表里重复出现。
                  注意：cache-type-k/v 是**按模型**各自生效的，
                  所以也放在这里，不在参数子表里。

六、KVMem 分支（llama-kvmem-server）
------------------------------
这是另一套程序：C:\llama.cpp\kvmem-llama.cpp\ 分支自带的
llama-kvmem-server.exe。它**不是**主路由的池成员（它自述
"Independent single-slot server. Does not patch llama-server."），
是另一个程序、单槽、一次只跑一个模型。
但它和主池**共用同一个服务 llama-router、同一个端口**
（config.host / config.port，默认 0.0.0.0:8080）——
这个服务跑的是**网关 gateway.py**，它占住 8080，后端只绑本机的
8081（主池）/ 8082（KVMem）、不对外。网关按请求里的 model 名
（id 或 alias 都行，大小写不敏感）把流量转给对应后端；两个后端
互斥，同一时刻只有一个在跑，切换由网关完成，调用方无感。

所以本工具给它单独开一个标签页「⚡ KVMem」，和主池共用同一份
模型清单（同一条 config.json models），但**不写进
router-preset.ini** —— 主 llama-server 不认识 --kvmem-* 参数。

* 标签页结构
    ① 档位区：列出所有 runtime=kvmem 的条目（单选，一次只能
       选一个），显示 ctx / 预算 / 预留 / 思考开关
       （端口是服务级的，统一在「全局」页，档位行不再各写一个）。
       「✔ 设为当前档位」写入 config.kvmem.active_id，
       下次重装服务按当前档位取参数。
       「➡ 去模型页编辑」跳到模型页改同一条记录
       （模型文件、mmproj、视觉、推测解码都在那边）。
    ② 运行服务区：应用并重装 / 切回主池 / 启动 / 停止 / 重启 /
       前台运行 / 刷新状态 / 打开日志。
       服务名就是 llama-router（和「服务」页是同一个，端口也是同一个）。
       「应用并重装」= 校验当前档位 + 写 serve_mode=kvmem 再重装服务；
       「切回主池」= 写 serve_mode=router 再重装服务。
       服务装的是网关 gateway.py，重装只是让网关重启、按 serve_mode
       拉起对应后端；平时发请求带谁的 model 名，网关就自己切到谁。
       改了任何参数都要**重新点一次「应用并重装」**才生效。
       另有 CUDA 设备输入（写进服务环境变量，不占配置文件）。
    ③ 参数区：常用 = kvmem-budget / kvmem-gen-reserve /
       enable-thinking / reasoning-budget / ctx-size /
       parallel / jinja；扩展里是 kvmem / kvmem-block-tokens /
       kvmem-query-policy / kvmem-method / ui-dir / verbosity
       等 9 个 KVMem 专属项。
    ④ 底部「💾 保存 KVMem 配置」。

* 模型清单怎么加档位
    两个办法，推荐第一个：
    ① 从分支自带的 bat 导入（见下面「从已有的 .bat 导入参数」）
    ② 手动：「模型」页 → 新增 → 把 runtime 改成 kvmem。
       （老字段 kvmem_port 已废弃：端口统一读顶层 port，不用填）
    已有 3 个档位（对应分支目录里那 3 个 bat，id 按 bat 名取）：
      编码档       ctx 262144  预算 24576  预留 12288  思考开
      快速问答档   ctx  32768  预算 16384  预留  4096  思考关
      长文档       ctx 262144  预算 32768  预留  4096  思考开
    三者共用同一个模型文件和 mmproj，区别只有上面这几项。
    在模型列表里，这 3 条会带「⚡分支」标记。
    三个档位共用 8080，但同一时刻只有一个在跑，不会冲突
    （跟主池也不会冲突——主池和分支本来就只会有一个在跑）。

* 从已有的 .bat 导入参数
    分支目录里的 start-*.bat 已经写好了一整套启动参数，不用一项项抄：
      「⚡ KVMem」页 → 「📂 导入 bat…」
      或「模型」页 → 「导入bat」
    弹出文件选择框，可按住 Ctrl/Shift 多选（只认 .bat，不认 .ps1；
    不扫目录，也不支持拖入）。

    导入时会做的事：
    1) 跑一次 <exe> -h，把短名和别名归一：
         -c → ctx-size，-n → n-predict，-ctk → cache-type-k，
         --no-X → X=false；认不出值的走启发式判断。
    2) bat 里**每一个** flag 都落进 config.json：
         · schema 里有的 → 打开该项并写入 bat 给的值
         · schema 里没有的 → 自动登记成「额外参数」
           （存在 user_preferences.json 的 extra_params），一个都不丢
    3) 先按 schema 把参数补齐、再**全部关掉**，只把 bat 里出现的
       置为写入 —— bat 是唯一真相，bat 没写的就沿用 llama.cpp 默认值
    4) 条目怎么认（按顺序）：
         同 id                                → 覆盖
         同 runtime + 同模型路径 + 关键档位参数打分
         （预算 / ctx / 预留 / 思考预算，每对上一个算一分）→ 覆盖原条目
         都不匹配                             → 新建
       覆盖时保留原来的 id 和 alias，所以「✔ 设为当前档位」的选择
       不会失效。你的几个档位共用同一个 gguf，靠打分各归各的，
       不会全灌进第一条。
    5) bat 里的 set K=V → config.kvmem.cuda_device / cuda_device_order
       bat 里的 --host/--port **不照抄**：主池和分支已统一用
       config.host / config.port（「全局」页改），导入报告会提示已忽略。
    6) 重新生成 router-preset.ini，刷新模型列表 / 档位区 / 两个参数
       面板，最后弹一个汇总框告诉你每个 bat 落到了哪条、登记了哪些
       额外参数、有没有失败的。

    重复导入同一个 bat 是幂等的（第二次结果与第一次完全一样）。
    分支档位照旧不写进 router-preset.ini。
    如果运行服务已经装了，导入后要**再点一次「应用并重装」**，
    新参数才会生效。

* 调用地址
    http://127.0.0.1:8080/v1 （端口就是「全局」页的 config.port），
    model 名就是条目的 alias/id（大小写不敏感，主池和 KVMem 都认）。
    「📋 复制调用地址」直接复制当前档位的地址。
    **主池和 KVMem 分支是同一个地址** —— 网关 gateway.py 按 model 名
    路由，同一时刻只跑一个后端；请求里写哪个组的名字，网关就把哪个组
    拉起来（首次切换要等模型加载，会慢几十秒，之后就快了）。
    没带 model 或名字认不出来时，交给当前正在跑的后端处理。

七、显存与空闲策略
----------------
空闲卸载时间：「全局」页 → 空闲 N 秒后自动卸载，默认 3600 (1 小时)。
llama-server 到点会调用 sleep，把模型从显存卸载到 RAM（保留 KV），
来新请求时自动唤醒。第一次唤醒可能要几秒加载回显存。

模型切换时的提前卸载：llama.cpp router 模式已经内置，**你不需要配置**。
每次请求指定不同 model 名时，旧模型会被自动腾出 slot 给新模型。

显存被其他程序抢占：可选启用 watchdog 守护。
  1.「全局」页 → 显存守护 watchdog → 勾选启用
  2. 设置阈值（如 2048 MB = 2GB）、检测间隔（如 10 秒）
  3. 切到「服务」页 → 点「安装 watchdog」
  watchdog 会定期查 nvidia-smi，低于阈值时主动
  POST /models/unload 卸载最久未用的模型，为其它程序腾显存。
  注意：watchdog 依赖 nvidia-smi（NVIDIA 驱动自带），需在 PATH 中。

八、常见问题
-----------
Q1: 提示「需要管理员权限」
A1: 以管理员身份运行 manager-ui.bat；或者只通过 UI 改配置，
    改完保存后右键 install-router.bat → 以管理员身份运行。

Q2: 改了配置不生效
A2: router-preset.ini 改了之后必须重启服务才会被 llama-server
    重新读取。UI「服务」页 → 「重启」一键搞定。

Q3: 提示找不到 llama-server.exe
A3: 在「全局」页把 llama_dir 改成你安装 llama.cpp 的根目录，
    该目录下要有 llama-server.exe 文件。

Q4: 想两个模型同时驻留
A4: 「全局」页 models-max 改 2（显存够时才建议）。

Q5: 全部走 GPU
A5: 「全局」页「可选参数」区，勾上 n-gpu-layers，填 99 或 auto。

Q6: 启动时弹窗说「服务无法启动」
A6: 多半是端口被占或模型路径错。先看「服务」页底部日志
    或 C:\llama.cpp\logs\router.err.log 里的真实原因。

Q7: Python 报错 No module named 'tkinter'
A7: Windows 重新跑一次 Python 官方安装包，确保 tcl/tk 组件
    被勾选。Linux: apt install python3-tk

Q8: 想要 UI 没有的高级参数
A8: 任何 llama-server 支持的 CLI 参数都可以加到 config.json
    的 model.params 里 (key 要和 CLI 一致
    如 spec-draft-n-max)，并在 UI 里勾选启用。
    注意：保存时 UI 会用本机 llama-server --help 核对一遍，
    本机版本不认识的 key 会被自动跳过不写入 ini（日志里会列出）。
    这是有意的 —— 一个不认识的 key 会让整个 router-preset.ini
    解析失败，所有模型都加载不了。

Q9: 保存后日志提示「本机 llama-server 不支持以下参数」
A9: 你的 llama.cpp 版本较老，还没编译进这些参数（如 n-cpu-ffn、
    lazy-mode）。它们已从 preset 里跳过，其余参数不受影响。
    升级 llama.cpp 后重新保存即可恢复写入。

Q10: 其它程序需要 GPU 显存时怎么办
A9: 三层机制按优先级：
    ① 启用 watchdog 守护：「全局」→ watchdog → 启用 → 「服务」→ 安装 watchdog
    ② llama.cpp router 自身：切换模型时旧模型自动腾 slot
    ③ sleep-idle-seconds：空闲到点自动 sleep 释放显存
    ④ 手动：UI「服务」页 → 停止 / 卸载 llama-router，把显存让给别的程序

九、打包分发给别人的方法
--------------------
A) 推荐：打成 zip 直接发
   整个文件夹压缩成 zip → 别人解压到任意目录 → 装 Python → 双击 manager-ui.bat
   优点：体积小、跨机器、免安装、可改源码。
   缺点：对方需要自己装 Python。

B) 进阶：PyInstaller 打成单 exe
   pip install pyinstaller
   pyinstaller --noconfirm --onefile --windowed ^
       --add-data "config.json;." ^
       --add-data "安装指南.txt;." ^
       --add-data "router-preset.ini;." ^
       --name llama-router-ui ui.py
   产物 dist/llama-router-ui.exe 单文件可双击运行（不需对方装 Python）。
   缺点：体积大（~15 MB）、杀软可能误报、首次启动慢。

C) 安装包：NSIS / Inno Setup
   完全图形化向导式安装，适合给完全不懂电脑的人用。工作量大。
   如果真要：建议先用 B) 的 exe 跑通，再让 NSIS 包成 .msi/.exe。

十、卸载
-------
双击 uninstall-router.bat（管理员），即可彻底删除 Windows 服务。
config.json 和模型文件不会被删，下次想用再 install 即可。
